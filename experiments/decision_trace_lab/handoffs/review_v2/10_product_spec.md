# 评审模块 V2 产品规格：结果优先、按需追因

## 1. 决策与目标

本轮改造的目标不是提高“已打标签事件数”，而是让评审者能以最少操作可靠判断一轮 Agent 回答是否可接受，并在不可接受时定位实际发生过的可疑决策节点。

**核心决定：** 评审入口从逐事件队列改为“最终结果卡”；事件级复核只在结果为错误、部分正确或无法判断时按需展开。未被人工选择的中间事件一律为`未复核`，不得由 UI、统计或存储推断为正确。

## 2. 结果优先评审流程（P0）

1. 打开最近一轮时，首屏显示“本轮结果卡”：用户输入的安全摘要、Agent 最终回答的安全摘要、结果类型（含 no_match）、必要上下文（如题目/章节/图片是否存在的脱敏状态）与自动异常数量。
2. 评审者对**最终结果**选择：`正确`、`错误`、`部分正确`、`无法判断`。其中“部分正确”是结果层级的产品状态；实现可先以现有 `uncertain` 契约承载，并在显示层明确其语义，直到数据契约升级。
3. `正确`：立即保存最终结果标签，显示“本轮无需继续复核”；不展开因果链、不创建中间事件标签，评审结束。
4. `错误`、`部分正确`或`无法判断`：展开“实际决策因果链”。默认按执行 sequence 展示该回合真实事件，突出最终结果和自动异常关联节点；不预设必须查看或标注的节点数量。
5. 评审者可勾选一个、多个或零个怀疑节点，再对选中的节点给出结论。可直接结束本轮，系统需明确“其余节点未复核”。
6. 全量原始事件 JSON 继续保留在折叠的“技术详情”，仅供排障，不作为默认评审任务。

## 3. 范围与非目标

### 范围内

- 结果卡、结果结论、按需因果链、可多选怀疑节点、事件标签和可选错误说明。
- 将已有 `scan_events` / 自动检查异常在结果卡和因果链中主动呈现，并可定位到相关事件。
- 已有标签修订语义：同一 target + dimension 保留 revision，最新标签为当前有效值。
- 保持 sidecar 观察/标注失败时 Agent 主业务响应、主线 DOM、主线静态资产和会话行为不受影响。

### 非目标

- 不要求评审者给出正确答案、改写最终答案或完成所有中间事件的评分。
- 不把自动异常当成错误判决；它只是一条待核验线索。
- 不改变 Agent 的工具选择、搜索/排序、主线响应、题库数据或授权行为。
- 不在本期做跨回合聚类、团队协作分配、标签质量仲裁、模型训练闭环或全量性能分析。

## 4. 优先级

| 优先级 | 必须交付 |
|---|---|
| P0 | 结果卡先于事件队列；正确一键结束；错误/部分正确/无法判断按需展开因果链；可任选多个可疑节点；未选节点明确未复核；原始 JSON 折叠；自动异常突出；全部写入保持 fail-open。 |
| P0 | 结果级与事件级标签可区分；错误原因可选；正确答案/期望结果可选且绝不阻塞保存；no_match 保留合理/错误/不确定分类。 |
| P0 | 侧栏桌面与移动端均可用，且不改变主线业务页面或隔离 cookie 行为。 |
| P1 | 结果卡中的安全上下文摘要、异常到因果节点的跳转/高亮、按“可疑/已复核/未复核”筛选和结果级统计。 |
| P1 | 将“部分正确”从展示语义升级为独立、向后兼容的存储枚举；在旧客户端仍能读取为 `uncertain`。 |

## 5. 数据契约

### 5.1 事件与因果链

- 因果链数据仅来自该 `trace_id + turn_id` 的真实事件，按 `sequence` 升序；不得合成固定步骤、不得以预期流程补事件。
- `turn_completed` 是结果卡的主目标；`intent_decided`、`tool_completed`、以及与异常直接关联的其他真实事件可成为可疑节点。
- `issues` 继续由扫描得到，至少保留 `code`、`turn_id`、可选 `event_id` 与诊断字段；前端只显示脱敏后的 code/安全摘要。

### 5.2 标签

现有追加式标签为兼容基础：

```text
target_type: "event" | "turn"
target_id: event_id | turn_id
dimension: "result_interpretation" | "intent" | "tool_output" | "causal_suspicion"
verdict: "correct" | "incorrect" | "uncertain"
no_match_classification?: "reasonable_no_match" | "false_no_match" | "uncertain_no_match"
reason?: string
error_category?: string
expected?: string
label_revision: positive integer
```

- 结果卡使用 `target_type=turn`、`target_id=turn_id`、`dimension=result_interpretation`。若当前后端只能接受 event target，P0 临时使用 `turn_completed.event_id`，并在迁移中补齐 turn target。
- `部分正确`在 P0 展示层映射为 `verdict=uncertain` + `error_category=partial_correct`；`无法判断`映射为 `verdict=uncertain` + `error_category=insufficient_evidence`。P1 可增加显式 `result_status`，但必须保持旧 `verdict` 可读。
- 可疑节点选择须落一条 `dimension=causal_suspicion` 标签或等价、可审计的选择记录；单纯展开/浏览不得形成标签。
- `reason`、`error_category`、`expected`均可选。`expected`永远不得成为提交 `incorrect` 或 `partial_correct` 的前置条件。
- 未建标签 = `unreviewed`，只可作为派生展示状态，不能写成 `correct`，也不能计入“已复核”。

### 5.3 安全与隐私上下文

- 评审结果卡可显示的上下文必须是服务端生成的白名单摘要，不能将完整用户文本、原始 prompt、模型回复、图片/答案路径、候选内容、headers/cookie/token/password/secret 等直接交给侧栏。
- 复用并扩展现有禁止键、超长字符串、绝对路径拦截：写入被拒绝时记录最小化诊断 code，观测失败自动降级，不影响真实 Agent。
- 错误原因和期望结果输入也经过同一隐私校验；被拒绝时提示“包含不允许的敏感或路径信息”，不回显敏感内容。
- 会话隔离继续以外部 `decision_trace_mainline_session` cookie 对应内部会话；旧 `tiku_agent_session` 不得争用 observed 会话。

## 6. 自动异常提示

- 结果卡顶部展示 `自动检查：N 个可疑点`；N=0 时显示“未发现自动异常（不等于结果正确）”。
- 有 `event_id` 的异常在因果链对应节点显示高亮、code 和简短解释；仅有 `turn_id` 的异常显示在链路总览。
- 自动异常默认不写人工标签、不改变最终结论按钮默认值；评审者仍可判为正确。
- 已存在的典型异常至少包括：未知事件、序列不连续、开始/完成事件基数异常、授权计数不一致、工具开始/完成不配对、嵌入式自动检查失败、隐私问题。

## 7. 移动端信息层级（P0）

1. 固定入口“评审轨迹”及结果状态/异常徽标；默认不遮挡主聊天。
2. 打开抽屉后，首屏仅显示：最终回答摘要、必要上下文、自动异常数、四种结果结论按钮。
3. 仅在非正确结论后显示“查看决策链”；链路节点采用单列卡片，异常节点置顶或高亮，支持多选。
4. 原始 JSON 位于最后的折叠技术详情，默认关闭；操作按钮最小触达高度 44px，状态与保存失败信息可读。
5. 桌面保留侧栏；窄屏继续使用覆盖抽屉。两端均不以“待复核数量”制造必须清零的暗示。

## 8. 验收标准

1. 新开一轮时，评审者无需先阅读事件 JSON，即可看到安全的用户输入/最终回答/必要上下文摘要和最终结果判断控件。
2. 对最终结果选择“正确”后，一次保存即可结束本轮；不会自动新增任何中间事件标签；界面明确其余节点未复核。
3. 选择错误、部分正确或无法判断后，系统只展示本回合实际 sequence 事件形成的因果链；可选择 0、1 或多个可疑节点并独立保存。
4. 错误或部分正确可在不填写 `expected` 的情况下保存；可选填写 `reason`、`error_category`，并且标签 revision 和最新标签读取逻辑正确。
5. no_match 的三类判断仍可保存，且不与最终结果标签冲突。
6. 未选择的事件在 API、统计和 UI 中均为未复核；不计入正确、错误或已复核。
7. 自动异常在结果卡可见，有 event_id 时可在因果链定位；没有异常不得显示为“已验证正确”。
8. 所有结果卡与说明字段通过隐私检查；禁止字段、绝对路径、超长内容均不会泄露到可见 UI/持久标签。
9. 小于等于 900px 时，侧栏变为可开关抽屉，结果结论先于链路和技术详情，仍可完成一次结果标注和多节点选择。
10. 观察面板请求、存储或标注错误不会改变 `/api/message`、`/api/message/stream`、`/api/image`、`/api/reset` 的主线响应；主线 DOM 与 `/assets/demo.*` 保持镜像一致，外部 cookie 隔离不回归。

## 9. 旧机制：保留、替换、迁移

| 旧机制 | 处理 | 迁移要求 |
|---|---|---|
| `intent_decided` / `tool_completed` / `turn_completed` 平铺“人工复核队列” | **替换为默认结果卡 + 按需因果链** | 既有事件标签和 revision 原样可读；旧事件仍可在技术详情和链路中显示。 |
| `correct` / `incorrect` / `uncertain` verdict | **保留** | P0 以 `uncertain + error_category` 表达部分正确/无法判断；P1 再增显式状态，读取端双读。 |
| `expected`、`reason`、`error_category` | **保留并改为结果/节点可选说明** | 不迁移为必填；现有记录不丢失。 |
| no_match 三分类 | **保留** | 仍绑定最终结果目标，并与结果卡同步展示。 |
| `scan_events` 与技术详情 | **保留并提升为主动线索** | 异常同时进入结果卡和因果链定位；JSON 仍折叠。 |
| `summary()` 的“关键项/已复核” | **替换统计口径** | 新统计分别报告“已判结果回合”“已选可疑节点”“未复核节点”；不得以未标注事件填充正确率。 |
| sidecar fail-open、镜像完整性与 cookie 翻译 | **保留，不得改弱** | 任何新接口/字段失败均局部降级，不能影响真实 Agent。 |

## 10. 实施边界提醒

本规格要求的是评审工作流变更，而非对现有事件数量做视觉重排。执行时如发现“安全摘要”无法从当前事件安全地得到，应先交付不泄露的最小摘要和明确的不可用状态，不得为追求完整上下文而放开隐私过滤。
