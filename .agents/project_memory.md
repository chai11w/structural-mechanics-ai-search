## Implemented

- A3-V1 以 `unit_id` 绑定题目/框/裁图，多题并发校验上限 10；单题自动下行 A2，异常回人工裁剪。服务端校验状态、编号空间和原样 unit 集合，防重复搜索/完成。
- 空分组按引用关系简化或拒绝；schema 错误只存 code/简因 30 天，题图/裁图/候选/答案在新对话或 2 小时后过期。
- 共享复筛为综合分 `>=90%` 全部，否则可靠 Top 3；8896/V1+Qwen 为 `>=95%`。V4/V5 未提升生产。
- 章节使用七存储键和 `supported|unsupported|uncertain` 三态；失败后仅经用户授权才全局搜字母库。
- 反馈 schema v8 要求 `rated_response_id` 和 conversation 目标一致，并校验 response 的 identity/session/有效期；旧 v7 行未绑定、只读兼容，案例媒体仍独立保存。
- 今日使用按上传父 workflow 统计发起页数、按进入 A2 的题目统计实际检索题数，同页多题分别计题、同题重试不重复；保留 `today_searches` 兼容别名。
- 费用归属稳定邀请码，父 A3/子 A2 共用账本；认证只存哈希，新邀请码用 AES-GCM，复制受会话、CSRF 和审计保护。
- 五态公共协议只输出注册 code/白名单字段，隐藏异常、路径、模型 reason 和凭据；候选原子交付，答案区分 0/部分/全部，同题重试沿用 `search_id`。
- 2.3 的运行根 `trace_events.sqlite3` 采用严格白名单、每 trace 唯一终态和有界异步写入，健康计数暴露失败；JSON/stream/媒体一致且不依赖 8795。
- 2.4 的运行根 `responses.sqlite3` 在公开前生成 `resp_<32hex>`，仅存协议、父子 ID、阶段、计数、耗时等白名单投影；覆盖 JSON/stream/A3/A2/可评分错误。同 trace 同投影幂等，冲突/写失败 fail-closed；反馈写入/删除按 response 所有权，回归已通过。

## Architecture Rules

- 8795 独立于 8790；Trace Store、Response Store 和诊断查询都独立于 8795，后者只可做可选只读 UI，不是 trace/response 数据所有者。管理员认证、Cookie、运行目录和控制数据不得与用户会话混用。
- 费用归属稳定邀请码，不按临时 Cookie；保留单码额度和全站上限。预算准入前检查、完成后落账；目录价格和 usage 只是估算，不等同供应商实扣。
- 8790 只读邀请码哈希；8795 加密保存新建/重置码。控制库与 AES-GCM 密钥一起迁移；迁移前只读核对 ID/哈希/状态/认证版本，冲突禁止写入。
- 反馈只保留必要上下文并到期清理；搜题耗时由服务端按权威 revision 从有界网页时间线重建“上传至首批候选”，忽略客户端直传 duration，但时间戳仍来自浏览器 `createdAt`，不能当服务端绝对耗时。反馈媒体必须复制到案例目录，不依赖短期会话路径。
- A3 反馈以目标 `response_id` 的服务端投影所保存的 revision、候选数、父 workflow/子搜索和协议上下文为准，不用客户端字段或会话最新状态覆盖历史快照。
- 修改检索、储存或索引逻辑时同步检查 CLI、飞书、Agent、8795 和项目 Skill 文档。
- 工具内部诊断与公共输出必须分层；新 Agent 的 HTTP/Web 出口只接受注册错误码和白名单字段，个人飞书入口不纳入这一公共边界改造。
- 8790/8896 的 A3-V1 裁图路径固定为 GLM bbox + Pillow；仓库中的 OpenCV/Paddle 模块是遗留实验，不恢复为生产依赖。
- live 题库根为 `D:\桌面\答疑、帮做\结构力学\帮做`，字母库为相邻 `帮做_字母库`；仓库 Excel 是历史副本。
- 题库写操作必须 plan → confirm → backup → execute；各服务端口、Cookie、状态、媒体和日志保持隔离。

## Known Risks

- GLM/A3 真实样本仍少，需验证多题混排、裁剪边界、小支座/小荷载、低清和旋转；观察期保留 8896 `--disable-auto-crop` 与 8897。
- 旧 `parse_chapter` 仍会把“第4章”映射为内部 `4力法`；8896 已改用严格目录并对纯数字返回 `uncertain`，其他未迁移入口直接复用旧接口仍可能误搜。
- 新理解层尚未证明可替代并行外荷载 A 层；A 应先保留并影子对照非题目、无外荷载、普通题和复杂多图题，达标后再退役。
- 影子预检失败只记录、不影响用户；A/B 取消不能撤回已发出的模型请求，仍需观察误拦截、长尾和额外费用。
- 邀请码被转发会共享同一 3 元额度；签名 Cookie 防伪造但不能阻止持码人主动共享。
- 费用完成后入账，最后一个在途任务可能略超阈值；usage/价格缺失也会造成估算偏差，30 元不是支付平台硬限额。
- `admin-tiku.cysbuting.cn` 已接入 Tunnel，但 Access/WAF 未启用，公网目前只有应用层管理员门禁且缺少登录失败限速。
- Qwen 冷调用有长尾，需继续观察 8790/8896 限流；8788 暂不切换。
- 飞书旧入口仍可能把顶层异常文字直接回复给个人用户；这是本阶段明确接受的内部入口风险，新 Agent 的公共输出保护不会覆盖它。
- 2026-07-29 曾有旧 API 密钥出现在进程命令行；旧进程已终止，用户暂不轮换。
- 2.3 事件写入为 fail-open，健康计数可显示丢失但不能补记；反馈目标已按 `response_id` 权威绑定，但 8795 的反馈到费用展示仍是 search/time 兼容 join。Response Store 有过期判定但尚无周期物理清理；反馈动态保留期和周期清理仍需在 2.5 核对。

## Do Not Do

- 不读取、提交或在工具输出、日志、项目文档中展示 API key、Tunnel token、邀请码明文、管理员密码、私有发放清单和本地敏感配置；管理员页面的受控复制功能除外。
- 不把管理员认证并入用户邀请码会话，不把 8795 部署进 8790 进程。
- 不因后台记录的 ID/哈希一致就假定旧邀请码可用；灾备切换还必须核对状态并验证登录和动态撤销。
- 不把邀请码身份改回会话 Cookie，不删除全站保险上限。
- 不跨章节搜索，不绕过项目脚本的识别、过滤和排序。
- 不在未授权时把图片发给外部模型，不重复已完成的题库原图付费评测。
- 不把新 Agent 的 HTTP/Web 公共输出改造扩展到个人飞书入口，也不随意停止或改造 8788；部署重启必须精确限定目标端口与进程。
- 不在目标回复缺失时保存整段反馈历史，也不把反馈专用框选图重复注入普通聊天消息。
