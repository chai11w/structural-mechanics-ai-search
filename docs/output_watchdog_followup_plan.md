# 输出看门狗后续方案

## 目的

本文件整理输出层实验的有效结论。实验代码不直接进入生产主线；后续以
`1102553` 为基线，在现有回复和现有模型润色之上增加轻量输出看门狗。

后续审查确认：看门狗不能承担工具错误分类和业务事实恢复。第一优先级已调整为补齐工具层结构化
反馈；详细现状、缺口和建议契约见 `docs/tool_feedback_phase1_audit.md`。看门狗只保留为最后一道
薄保险。

## 已确认的问题

1. 旧回复出口分散，错误分支可能把未知错误、英文异常名、本地路径或内部细节拼进用户文本。
2. `render_answer()` 只看答案路径，不能证明图片实际已经持久化并交付。
3. 缺章节、缺题号、缺候选号、编号越界被合并成笼统提示时，用户不知道下一步输入什么。
4. “请按当前可用操作继续”不能单独作为用户指引；如果页面没有显示全部操作，这句话不可执行。
5. A3 原有的题号、取消范围、当前题和剩余题数说明是有价值的，不能被统一模板抹平。
6. 安全意图识别和安全回答模型润色是两件事：识别要保留，低风险自然表达可以继续交给受限模型。
7. 模型生成后又被固定模板覆盖会产生无效调用、额外等待和费用。
8. 自启看门狗直接从工作区启动脚本，因此未完成验证的工作区改动会在下次开机加载。

## 保留原则

- 正常候选、全局搜索、候选拒绝、无匹配、重发答案、取消和 A3 具体引导，先保持现有文案。
- 章节支持范围、外荷载门禁、裁剪结果等事实性内容继续由规则决定。
- 问候、致谢、告别、身份、能力、流程说明和普通闲聊继续保留原安全识别线路。
- `SafeAnswerGeneratorV0` 的模型润色、契约校验和固定回退继续保留，默认行为按原配置决定。

## 只修正这些问题

- 答案或候选的成功文案必须以实际媒体交付结果为准。
- 未知错误不再拼接原始错误字符串；只使用有限的中文原因分类，无法分类时使用固定安全失败提示。
- 缺章节、缺题号、缺候选号和越界分别给出具体可执行指引。
- 不再把“按当前可用操作继续”作为唯一用户提示；允许操作必须由按钮或明确文字呈现。
- 章节补充后若本回合已得到真实候选、无匹配或错误，回复必须反映本回合真实结果。

## 看门狗行为

看门狗只检查最终准备发送的文本，不参与检索、意图判断、状态机或候选排序。

```text
现有规则回复 / 现有模型润色
              |
           看门狗
        /      |       \
     正常   轻微异常   危险异常
      |        |          |
    原样发   安全润色   固定安全回复
```

### 正常

- 非空、长度合理、无控制字符；
- 没有内部错误、路径、凭据、堆栈、命令或原始 JSON；
- 事实、数字、题号、章节和操作与业务结果一致。

正常文本原样发送，不重新改写。

### 轻微异常

只是表达生硬、机器味重或解释不自然，但不含内部敏感信息时，可以交给受限模型润色。
模型只能改表达，不能改变事实、状态、数字、题号、章节、候选数量、答案交付状态或允许操作。

### 危险异常

命中系统命令、代码/原始 JSON、`Traceback`、`Error`/`Exception` 堆栈、本地路径、URL 凭据、
token、密钥、prompt、reasoning 或内部诊断时，不把原文直接展示给用户。先归类为安全中文原因，
然后可做受限润色；润色失败就回固定安全回复。

## 交付顺序

1. 以 `1102553` 恢复运行主线。
2. 盘点工具反馈，拆分内部诊断、私有数据和可公开安全事实；按稳定 code 生成确定性中文语义。
3. 先修复已知工具错误穿透，再分别处理媒体交付真实性和 HTTP/流式异常映射。
4. 只有安全事实完整但表达确实需要改善时，才让受限模型润色安全草稿；模型不能读取原始异常。
5. 最后以旁路模式验证薄看门狗，只检查明确泄漏和事实矛盾，不改正常回复。
6. 用正常规则、正常模型、错误、A2、A3、媒体失败和安全闲聊样本回归；8790、8896 独立验证后再讨论部署切换。
