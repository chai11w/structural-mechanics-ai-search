# 裁剪兜底中的连接中断与英文异常

用户在裁剪兜底时看到 `signal is aborted without reason`。前端后台任务客户端的 15 秒请求超时会触发原生 AbortError，`http()` 没有归一化异常，`backgroundNotice()` 又直接使用 `error.message`，因此浏览器英文出现在业务页面。仅凭截图不能断定当时是哪次网络请求或为什么超过 15 秒。

## 本次修复

- 后台任务 HTTP 和控制请求把中断、网络失败及无效 JSON 转成固定中文提示。页面各异常出口只使用明确的用户提示或该场景的中文默认提示，不直接渲染原生异常消息。
- `/api/jobs/session` 只绑定会话，不启动模型或检索；核对服务端的幂等绑定实现后，允许临时网络失败时自动再连接一次。业务任务 POST 不因此重复。
- 绑定阶段失败时标记“尚未提交”，释放本次尚未发送的浏览器请求标记，不生成待查业务任务。裁剪范围保留，原提交按钮仍可使用。
- 已提交任务的断线仍只查询原任务。真实浏览器测试发现聊天里的重连按钮会被裁剪面板覆盖，因此在裁剪面板内增加了可点击的重连按钮。错误指导文字在重绘和窗口缩放后继续保留。
- 已收到注册业务错误时保留其含义；不会被随后发生的页面取消信号改成普通超时。旧 UNKNOWN 模型任务与费用记录不重放、不清理。

## 验证边界

后台客户端新增覆盖：绑定中断后仅补一次连接、持续绑定失败时零任务提交、业务响应丢失后只查询、无效 JSON 不暴露底层消息。相关前端、任务状态和 A3 HTTP 回归 25 项通过，其中后台客户端包含 25 个独立检查。

新增真实 Edge 浏览器故障脚本 `tests/phase6_crop_transport_browser.js`。隔离环境使用真实 A3/A2 状态、SQLite 和后台任务流程，模型由替身承担；注入真正的 AbortController 中止、连续观察断线及已接收任务的回执丢失。检查裁剪范围保留、重新提交可用、任务不重复提交、面板内重连、手机宽度下按钮可见和中文提示。未向外部模型发送图片或请求。

本修复解决错误展示和裁剪连接恢复，不声称消除了公网网络超时或千问超时。线上发布结果另行补记。
