# 飞书统一写入的事件入口

飞书存题和删除已在开发分支接入与力答相同的固定计划、永久题号、一次确认和私有写入器；支持持久草稿、图片、接收队列、后台作业与结果回执。当前是源码及隔离验证交付，没有修改正在运行的飞书服务或配置，不能凭此文启用受管生产写入。

## 已实现

`scripts/feishu_event_security.py` 在解析业务身份前校验原始 HTTP 字节上的 SHA-256 签名，检查时间戳、nonce、请求大小和重复签名头。配置加密推送时解密 AES-256-CBC/PKCS#7 事件，校验 Verification Token、应用 ID、真实 user/open_id 及消息身份；拒绝重复 JSON 字段和混合加密外壳。校验令牌在交给下游前移除。

协议依据为飞书官方 [接收事件说明](https://open.feishu.cn/document/server-docs/event-subscription-guide/event-subscription-configure-/encrypt-key-encryption-configuration-case)、官方 SDK 的 [事件校验](https://github.com/larksuite/node-sdk/blob/main/dispatcher/request-handle.ts) 与 [AES 解密](https://github.com/larksuite/node-sdk/blob/main/utils/aes-cipher.ts)。签名使用原始请求正文，不把解析后的 JSON 重新序列化后验签。

`FeishuHandler` 将有界原始正文和原始请求头交给验证器。严格模式下，直接调用旧 `handle_payload` 不能绕过验签。通过验证的发送者身份在处理线程中显式绑定，离开当前处理即撤销；不能把正文里的 owner 标志或收费管理员自动登记当作维护权限。

新增、补答案及删除入口在配置维护者或启用 `TIKU_BANK_STORE` 时要求当前已验证身份属于独立维护者清单。受管模式的原 `FeishuStoreService.apply_plan` 和 `FeishuDeleteService.apply_plan` 拒绝直接写 Excel/图片。配置管理适配器后，由 `FeishuBankManagement` 调用统一写入器；仅启用旧写入保护而未配置适配器时不能存题。未配置这些新模式时保留旧行为，正式迁移前仍须治理所有实际旧写者。

## 保留的操作与进度

1. 发送 `+` 进入新增，立即预留永久题号。发送题图后提示“正在识别”，复用现有飞书识别器。
2. 章节不确定时补选章节；依次发送多张答案图，每次回复已保存的数量。
3. 答案发完回复 `1`。先提示“正在核对题目和答案”，后台准备完整候选，成功后发送冻结字段、题图、全部答案和确认提示。这次 `1` 只是结束上传。
4. 全部预览发送完成后回复 `1`，才持久保存本次所有者确认，并提示“正在存入”。后台使用原操作继续执行，不要求再到力答确认。
5. 只有写入器报告 published 才回复成功，包含永久题号、章节、答案数量、操作编号和发布序号。准备、等待写入与成功分别显示，不把超时当作失败，也不把收到确认当作入库成功。

支持 `状态` / `进度`、`入库记录`（本对话最近十条）、`继续任务 <任务编号>`、`0` / `取消`。确认后仍在执行时，会明确提示其他新指令尚未执行；不会悄悄把新指令当作第二次确认。草稿可用 `修改尺寸 …`、`修改结构类型 …`、`修改单边尺寸 …`、`修改章节 …` 更正，修改时撤销旧批次和批准，再重新预览。

已有题可用 `删除 <永久题号>`、`删除刚才存入`、搜索后 `-候选序号` 准备删除；搜索候选必须绑定当前发布版本并能唯一定位永久题号，不能按旧行号删除。`替换答案 <永久题号>` 接收完整的新答案，预览原题、原答案与替换后图片，确认后整组替换，原题号不变。此处是明确命令的飞书适配；自然语言多图配对和任意字段修改仍由力答 DeepSeek 的现有受控草稿工具承担。

## 持久状态与恢复

`FeishuBusinessStore` 使用独立 SQLite（FULL 同步）保存应用身份、按发送者及聊天隔离的任务、可信消息和回复。重复事件或同一消息换事件编号投递均沿用原记录，内容改变则拒绝。图片按内容摘要独立保存，短事务不跨识别调用或网络请求；服务目录持有单实例系统锁。

准备/确认作业和原消息引用在调用写入器前一并提交。重启后从原任务、批次键、题号和确认继续；确认作业必须再次校验原消息身份、展示时点、冻结内容与批准摘要。改草稿会撤销旧计划，旧预览或迟到的进度消息不会继续展示。预览图片发送失败时不记为可确认。

识别失败保留原题图，不自动反复调用模型；回复 `重试识别` 使用原图继续。后台请求异常和回复发送重试最多五次，之后暂停；结果不明时保留原确认，查询状态可继续原操作。成功回执发送失败不触发第二次写入。飞书回复接口结果丢失时可能重复展示同一回执，不能宣称消息传输恰好一次。

这些持久保证覆盖题库管理资料。原飞书搜索会话仍使用原有临时会话规则；本次没有把搜索过期冒充管理资料删除，也没有实现两个渠道直接接管对方未完成草稿。

## 配置与部署前提

- `FEISHU_ENCRYPT_KEY` 或服务端私有配置 `feishu_encrypt_key`：事件签名/加密密钥。
- 现有 Verification Token 和 app_id 必须同时配置。
- `feishu_bank_maintainer_ids`：显式允许维护题库的飞书 open_id 列表，与费用查询管理员分开。
- 配置加密密钥、维护者清单或 `TIKU_BANK_STORE` 任一项时启用严格事件入口；配置缺失时拒绝启动，不退回无校验模式。
- 加密解码使用当前题库 Python 环境已有的 `cryptography`。独立服务环境必须预检此依赖及系统时钟。
- `FEISHU_BANK_MANAGEMENT_CONFIG`：服务端私有 JSON 配置路径，必须同时配置可信事件和 `TIKU_BANK_STORE`。`dry-run` 不能启用管理适配器，防止未发送的预览被当作可确认；联调使用隔离题库和传输替身。

管理私有配置只包含下列字段，不从消息或模型参数获取：

| 字段 | 含义 |
| --- | --- |
| state_dir | 飞书独立业务目录，不能与源码或正式发布题库包含/重叠 |
| published_store | 与 `TIKU_BANK_STORE` 相同的只读发布目录 |
| writer_url | 显式端口的 `http://127.0.0.1:端口`；禁止代理、重定向、其他主机和附加路径 |
| accounts | 维护者 open_id 到 prepare_file / owner_file 的映射，必须与维护者清单完全一致 |

每个凭据文件仅含 token 和对应 subject。写入服务中的凭据绑定相同所有者 principal、feishu 渠道、真实 open_id 和 prepare / owner 角色，批准凭据仅在可信渠道后台使用。`BankWriterClient` 不提供 execute，也不是模型工具；力答仍为原有三个管理工具加 Skill 加载器，无需新增必经 Skill。

## 验证边界

平台工作区的 `tests/feishu_management_test.py` 用已签名的真实 Bridge 请求、持久 SQLite、真实私有 HTTP 写入服务和 Excel/媒体版本验证新增、改尺寸、多答案、替换、删除、同一题号、取消、跨聊天拒绝、重复投递、未发完预览、重启继续准备和确认、确认响应丢失及识别显式重试。飞书网络传输和图片识别使用替身，没有发送真实消息。

正式接入仍需旧题号及预留关系迁入、真实维护者和服务凭据、目录权限与独立身份、回滚/容量/保留策略、真实飞书和 8790 兼容验收，以及所有者单独的部署授权。现有 `RecentEventIdCache` 继续用于旧搜索路径；配置管理的维护者消息使用持久队列去重。
