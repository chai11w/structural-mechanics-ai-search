# 发布题库的共享内容存储

`PublicationStore(..., incremental=True)` 启用 `bank_objects.py`：内容按 SHA-256 写入受控的 objects 区，冻结与发布目录通过硬链接引用，不再为每次变更复制整库媒体。manifest schema 1、旧版本绝对路径、批准回执、永久身份、读取锁与原子发布指针保持兼容。

旧完整版本不会原地转成硬链接。升级时一次性准备当前内容到对象区；后续候选只独立修改 Excel，链接不可变媒体，新内容在冻结时写入。所有版本完整字节仍在验证边界重新读取和校验。共享文件必须能证明与对象区相同文件身份，其他外部硬链接仍拒绝；存量冻结计划不改摘要或批准。

每个物理对象最多使用 900 个入口，接近 NTFS 链接限制时创建下一个同内容分段。不会每次保存都生成内容副本。对象区与私有候选必须同卷，ACL 限制为写入器可写；工作进程的写保护禁止修改共享文件及元数据。旧的普通写入脚本不能指向这些文件。

`published/current/main` 提供固定浏览入口，Windows 使用目录联接；恢复及发布完成后随 active 指针刷新。检索继续按 active.json 固定具体版本，不通过浏览入口定位在途候选，也不依赖写入服务运行。

新计划带 `storage_policy: content-objects-v1`，冻结前完成 Excel/媒体/题号语义检查。执行时全部字节与批准清单一致即可，不重复解析语义。旧计划继续原检查，要求独立旧库备份的历史冻结计划仍复制独立文件。

历史文件和原备份不自动删除。目录工具通常按逻辑大小重复统计硬链接，实际增量须按文件身份或对象新增量统计。未来启用历史清理、对象回收和整套冷恢复前必须适配对象及分段；它们当前未启用。出现新共享版本后，写入器不能降回不识别此格式的程序；已有只读 CLI、Agent、8790 和飞书检索接口仍读取 schema 1，模型工具及 Skill 流程无须变化。

专项测试 `tests.test_bank_objects` 覆盖增量字节与文件身份、外部链接拒绝、内容篡改、链接分段、四个真实进程中断点恢复和固定入口。平台完整 872 题隔离新增测量与更新入口见平台 `docs/bank-incremental-storage.md`。
