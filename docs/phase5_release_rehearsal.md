# 阶段 5 隔离迁移与发布回退演练

本演练使用临时目录、独立 SQLite、计数 fake 模型和真实 CLI 子进程。没有读取生产状态、调用外部模型或切换服务。测试入口为 `tests/test_execution_release_rehearsal.py` 与 `tests/test_execution_migration_publish.py`。

## 执行路径与断言

1. 建立匹配的旧 A3 整页、A2 子题与 clone 内图片，通过 `tiku_execution_migrate.py plan/apply` 迁移。源库和 SQLite 源备份的审阅摘要一致；新库读取的标准化业务态与旧读取器一致，父记录/子记录/unit 精确关联，只有 legacy_snapshot，不制造操作、尝试或调用。未带操作身份的 runtime 请求拒绝，调用数 0。
2. 新操作发生前，从迁移源备份读取旧 A2/A3 状态，核对图片可读。此时允许退回经验证的旧状态；这不证明新写后直接切回旧库安全。
3. 新运行产生一个已确认模型调用（100 输入、20 输出 token），注入费用账本写入失败。真实维护 CLI inspect 显示待记账 1；cost-plan/apply 校验审核哈希并备份执行/费用库，补账后待记账 0、调用仍为 1。
4. 确认没有 REGISTERED/RUNNING/UNKNOWN 操作。真实 cleanup-plan/apply 删除一个已过期无引用测试图片，保留原图和仍有效操作。测试只将隔离运行策略的历史保留期设为 1 秒并等待过期，生产默认值不变；mtime/ctime 双重保护正常启用。
5. 从清理前的已结账 SQLite 备份恢复到另一个执行库路径，按备份清单还原孤儿文件字节。保持同一媒体与费用路径，重新构造 runtime 后重发原键，返回同一 operation_id，模型调用数仍为 1、账本一行共 120 token。检查新库、恢复库和费用相关备份的 quick_check 与 foreign_key_check。旧源数据库摘要始终不变。

## 发布中断与竞争

- 非法旧状态和导入保存后异常都不能发布正式目标库；普通异常清理本次临时文件。
- 独立 Python 进程在首次导入保存后 `os._exit(91)`，不运行 finally。正式目标不存在；残留临时库标记 incomplete，正常执行读取器拒绝打开；源库和备份摘要一致。
- 导入过程中每次保存时正式目标仍不存在；全部成功后目标库才可读。
- 文件写入期间另一方创建最终名称，本次发布报 FileExistsError，另一方字节完整保留。

## 回退范围

生产启用仍需单独安排：冻结新请求并确认没有活跃执行，核对待对账调用和费用，备份固定代码版本、执行/费用数据库及媒体。存在未知副作用时不能通过切换旧库假装撤销。新写后的恢复需要保留新执行记录和费用身份，并使用兼容的执行读取器；本演练不保证任意旧版本可以读取新库。

本演练恢复到独立数据库路径、保留原媒体/费用路径；移动整个运行目录及自动路径重映射不在此证据范围内。未实现生产发布器，也没有执行 8790 的部署或回退。
