# 持久检索引用检查

`tiku_shared.bank_reference_snapshot.SearchReferenceSnapshot` 收集仍需保留的发布版本编号，供后续 30 天保留维护使用。它是部署者使用的只读库，不是模型工具；不删除文件、不迁移数据库、不续期、不写查看审计，也不批准清理。

## 输入与范围

调用者提供明确的 `ReferenceSource(name, kind, path)` 列表，以及包含 `published` 的 `CheckpointBankCatalog`。数据库路径必须是绝对路径；名称和路径不能重复。支持以下实际持久状态：

| kind | 来源 | 保留依据 |
| --- | --- | --- |
| `agent` | `SQLiteSessionStore` | 尚未过期的 Agent 状态，包括旧候选和答案路径 |
| `a3` | `SQLiteA3SessionStore` | 尚未过期的父任务状态，包括嵌套图片路径 |
| `execution` | `ExecutionStore` | 当前 epoch 且未过期的状态；另外保留执行账本、结果及待交付记录中仍持久存在的引用 |
| `checkpoints` | `SQLiteCheckpointStore` | 尚未过期、通过原记录完整性校验的检查点结果 |

扫描全部已配置来源才返回成功。必需数据库缺失、未知表或不支持的状态格式、坏记录、身份不一致、无法定位的发布路径，以及超出扫描预算均拒绝；不返回部分成功，也不把缺失数据库当作零引用。过期行同样解析并校验，但不由本命令删除。A3 的页面错误表不作为可继续业务状态。

执行账本中的历史结果可能超过会话期限，仍可能参与重放或交付，所以保留其引用直到原执行状态维护者移除对应记录。当前状态按持久 `expires` 判断；如果部署使用更短的 epoch 最大年龄，可能额外保留一段时间，不会据此提前释放版本。`live_rows` 对执行辅助表表示仍持久存在的行，不全是活跃会话。

发布图片的绝对路径必须落在配置根目录下的 `versions/<64 位版本>/main/…` 或 `symbolic/…`。逻辑引用沿用 [检查点引用契约](checkpoint_v1_contract.md)，旧 `main/current` 按可信目录映射处理，新 `published/version` 保留明确版本。只收集引用，不读取图片或验证发布清单：某版本被列出不等于它的文件完整或可恢复。

该库只证明**配置内的检索来源**已经扫描。它不能自行发现漏配的运行实例、确认实际运行代码或账号权限，也不包括力答/飞书管理草稿、写入计划、回滚和回执。后续维护必须绑定部署清单及这些管理引用；新建、停用或迁移状态来源时先更新可信配置。检查点数据库首次采集前可能尚未创建，不能通过省略来源来猜测服务没有引用。

## 一致性与失效

扫描期间持有发布根目录的共享读锁。每个来源通过 SQLite `mode=ro`、`query_only=ON` 打开，在读事务中扫描已提交状态，包含 WAL 中尚未合并到主文件的提交。返回清单前结束读事务，避免在等待维护时持续占用事务。

数据库连接保持到上下文退出。`assert_unchanged()` 使用原连接的 `PRAGMA data_version`，同时复核主文件身份、大小、修改时间及数据库/旁路文件的链接情况；其他连接提交或文件替换会使旧清单失效。关闭上下文后不能再调用这项检查。检查点合法延长保留期同样使旧清单失效。

SQLite 的 `data_version` 只能在同一连接上比较，不能把数值保存后与新连接比较，见 [SQLite PRAGMA 文档](https://www.sqlite.org/pragma.html#pragma_data_version)。只读 WAL 访问仍使用 SQLite 的正常旁路文件与锁协调，目录权限可能影响能否打开；不能用 `immutable=1` 读取正在更新的数据库来省掉协调，否则无法满足这里的读取要求，见 [SQLite WAL 文档](https://www.sqlite.org/wal.html#read_only_databases)。测试中的“业务数据库字节未变”不代表 WAL/SHM 协调文件没有任何元数据变化。

默认预算为全部来源合计 100,000 行、每字段 2 MiB、编码后合计 128 MiB、扫描时间 10 秒。预算仅可在上限内配置，时间上限为 30 秒；JSON 不允许重复字段和非有限数，引用遍历限制嵌套深度。SQLite 进度回调与行检查尽力中断超时，操作系统磁盘 I/O 和读锁等待并非可强制取消的硬超时。正式维护须测量实际状态规模；扫描期间回滚日志模式的数据库写者可能短暂等待。

## 调用方式

```python
with SearchReferenceSnapshot(sources, catalog=catalog) as snapshot:
    report = snapshot.report()
    # 调用者先取得原写锁、停住管理写者，再尝试短时 maintenance_gate。
    # 在同一独占区间内复核部署、管理引用与具体清理计划。
    # 仅当这些条件全部满足时调用：
    snapshot.assert_unchanged()
```

上例只说明连接生命周期，不构成完整清理流程。已保存的 JSON 报告不能代替最后的锁内复核。它包含扫描时间、配置摘要、各来源计数及内容摘要、受保护版本和报告摘要；不包含会话标识、原状态或私有路径。各来源的内容摘要针对被读取的业务行，不是完整数据库或部署配置的认证。

目前没有历史过期状态或删除入口。完整流程仍需 [发布维护约束](lida-bank-publication.md)中的单写锁、实际读者升级、完整备份与恢复核对、管理引用、30 天边界和中断恢复。
