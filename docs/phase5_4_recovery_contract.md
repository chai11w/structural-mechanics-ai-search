# 5.4 失败、费用与父子收尾（进行中）

2026-09-09。本文件区分已实现与待验证范围，不代表第五阶段已经完成或上线。

## 已实现：调用记录与费用交接

启用执行门时，`timed_model_call` 在调用前持久建立 `execution_effects` 的 PREPARED 记录，再提交 SENT，才执行 provider function。结果及费用白名单保存成功为 CONFIRMED；网络异常、确认失败或旧租约失效保留 UNKNOWN。每次 schema 纠错是新的 call ID，继承 operation/attempt/run；不记录 Prompt、模型正文、原始 OCR 或异常消息。

Qwen 的 `request_json_with_retry` 在执行作用域内不进行网络重试；检索链创建的 Zhipu SDK client 同样将 max_retries 设为 0。未启用阶段五的 CLI/旧飞书保留现有行为。上层 schema 纠错可在已有明确响应后发起新调用；若任一调用 UNKNOWN，新模型调用在发送前拒绝，外层即使捕获异常也不能把操作提交为成功。

`execution_collectors` 保存费用 collector 的最小元数据及允许的目标账本摘要。已确认调用立即保存独立费用记录；运行结束时 `execution_cost_outbox` 先持久保存完整费用写入载荷及 fingerprint，再写实际账本。账本事务成功后单独确认 outbox，因此成本库不可用不会要求重新执行业务。

费用写入在阶段五作用域内按不可变 run/call 内容核对：同 ID 同内容复用，同 ID 不同内容拒绝覆盖。`reconcile_cost` 只重发原账本事务，核对配置绑定的账本路径摘要及载荷摘要；已提交但 ACK 丢失也不会增加费用行。冲突记为 CONFLICT。普通未启用执行门的账本调用默认仍拒绝重复 ID。

如果进程在调用记录确认后、outbox 创建前中断，`stage_unwritten_cost` 可在原操作不再持有有效租约时，从完整的确认记录生成 outcome=interrupted 的费用载荷，再调用 `reconcile_cost`。存在未确认调用、缺失用量或仍在运行的操作时拒绝推断。供应商返回内容但没有 usage 时，业务结果可保存，费用仍待核对，不能当成零。已发送但结果未知时也不把错误记录中的 0 当作确认费用。

待写费用或已停止操作的未知费用会阻止该统一执行库接受新的业务操作；原成功收据及只读状态查询仍可用。这是保守的全库准入策略，不把未落账调用排除后继续消耗全站额度。`GET /api/operation` 新增按状态汇总的 effects 和 accounting.pending_runs，不暴露 token、原输入、账本位置或原始结果。

容量与保留沿用执行库上限；调用记录另限操作上限的 20 倍，每次发送前检查磁盘和数据库空间。普通维护不清理未知调用、待记费用或账本缺失的已确认调用。尚未实现自动维护调度或生产运维承诺。

## 已实现：子题收据与文件发布

子 A2 的最后一次状态保存与 `execution_handoffs` 的 CHILD_READY 收据使用同一 SQLite 事务。收据保存冻结的公共结果、父/子任务记录外键、unit、child 状态版本及原 operation/attempt。收据保存失败时回滚该次子状态和任务历史；父流程中断时保留已确认的子结果。父 `_after_a2_response` 按 A3 → A2 → SQLite 锁序完成父状态和 PARENT_APPLIED 确认，父事务失败不回滚先前已提交的子收据。整个操作成功后收据标 COMMITTED。显式恢复按下节执行；没有子收据的中断不能据此自动重跑。

上传副本、裁图、叠加预览和答案副本采用同目录临时文件、完整写入/同步后原子重命名。阶段五将路径、临时路径、内容摘要和发布状态记入 `execution_files`，未确认发布不能提交操作成功。新答案副本位于独立子目录，保留旧操作的答案引用；叠加预览使用唯一文件名。操作记录关联文件时暂不被普通收据清理删除，文件清理须等带引用核验的计划入口完成。

## 已实现：显式恢复及在途控制入口

`recover_operation(session_id, source_operation_id)` 及 `POST /api/execution/recover` 消费原 UNKNOWN 操作的子收据。必须匹配当前身份、会话代次、生产版本、父任务/unit 和子状态版本；所有已记模型调用须确认、所有文件须完成发布，结果引用还需通过现有摘要校验。恢复只完成父状态和公共结果投影，不重新调用模型、检索或复制答案。成功后原操作与恢复命令分别保存收据，原操作键再请求也只重发结果。条件不满足时整笔恢复事务回滚，不留下新 UNKNOWN 命令。

`control_execution(session_id, scope, target)` 及 `POST /api/execution/control` 要求精确目标：整页为 `{workflow_id, task_revision}`；A3 当前子题另加 `unit_id`；独立 A2 子题为 `{task_id, task_revision}`。scope=child 只停止当前子题并保留本页，scope=workflow 结束整页；reset 另行轮换会话代次并清空父子状态。旧键重发不会清除后来创建的新任务。控制动作允许在费用待核对时执行，但不会消除费用待核对记录。

这些命令在统一 SQLite 事务中登记、使旧执行者失权、更新状态并完成收据，不等待外部调用所持有的 Python 会话锁。HTTP 的 v6 控制通道同样不等待普通请求的 busy 标志；短控制事务成功后才确认相关 fence，普通请求的 busy 生命周期仍由原请求结束。`GET /api/execution` 提供一次数据库事务内的父子状态与 execution context，不执行模型，也不确认仍在途的浏览器 fence。命令失败的 HTTP 状态快照使用相同读取方式，避免错误出口再次等待模型锁。

`tests.test_execution_handoffs` 当前 13 项通过，含真正阻塞模型替身的 HTTP stream 请求：只读查询、停止子题和 reset 在释放调用前返回，旧请求随后不能写回；HTTP/runtime 重复恢复不增加识别次数，改变原恢复命令被拒绝；非法目标事务回滚。此证据覆盖服务端入口，不代表浏览器交互已接线或多 unit 部分成功已恢复。

该批最终全仓 **1529 项通过（102.999 秒）**，日志 `.tmp_phase5_1/commands_full.txt`；现有 CLI、飞书及默认未启用阶段五的服务保持原入口行为。仅本地隔离实现与验证，未推送、发布或操作运行中的服务。

## 已实现：多题准备的独立结果及受控复用

`execution_unit_batches` 与父 AUTO_VALIDATING 状态在同一事务建立，绑定原操作、父任务记录及准确的 unit 列表；显式准备和上传后的自动整页准备使用同一机制。每个 worker 在调用前建立 `execution_unit_checks`，函数返回后独立保存结果，不等待其他 unit 或父批次收尾。记录绑定 operation/attempt/parent/unit，保留输入摘要、确认状态及有限结构化结果；未确认的检查或批次阻止原操作成功。

恢复入口在没有子 A2 收据时，可以读取该批次的确认结果，恢复到选题状态。父最后保存前中断、后续 unit 尚未提交时，都不重新理解整页、定位裁图或校验已成功的 unit。已开始但结果未落盘的 unit 保持 UNKNOWN，不能把“没有收据”当作“没有调用”。存在未知外部调用时仍由原副作用门拒绝恢复。用户明确重新准备失败项时，新调用使用新操作/费用身份；已确认成功项可以复用。

复用摘要覆盖源码和 runtime 生产版本、校验器/荷载筛查器配置版本、原图与裁图字节、bounds、unit 和整页理解。图片或已记录的配置变化时不复用旧校验；选题入口也检查该摘要。运行源码指纹新增 `scripts/**/*.py`，覆盖被核心流程导入的模型适配与尺寸识别代码。具体版本约定见下节。

旧 Qwen 荷载和尺寸 JSON 缓存不具备上述操作来源信息。阶段五调用作用域内不读取、不改写这些缓存；显式新操作正常调用模型，同操作重发只使用持久操作收据。普通 CLI/飞书未启用该作用域时保留旧缓存行为。

专项验证包括部分失败后只重试失败项、worker 已保存但父未收尾、第二题尚未提交、检查结果写入失败保留 UNKNOWN、改变模型配置或裁图字节拒绝旧复用、上传自动准备恢复时不重复整页理解/裁图定位。真实 SQLite 费用专项使用模型替身，恢复后仍只有两条调用、合计 240 tokens；未发出外部模型请求。缓存专项验证已有缓存不被阶段五复用或覆盖，退出作用域后旧入口仍命中原缓存。

## 已实现：校验组件版本边界

`execution_versions.component_version` 对标准 Qwen 裁图校验器、Qwen/智谱外荷载筛查器读取 model/endpoint/timeout；指定 Prompt 文件则每次读取实际字节并计算摘要，路径相同但内容改变会失效。文件上限 1 MiB，缺失或超限拒绝复用。版本输入只在内存中形成，执行记录只保存摘要，不保存 Prompt、配置值或密钥。

自定义校验器/筛查器（含标准类的子类）必须提供非空 `execution_version`，值可以是有限 JSON 或每次返回有限 JSON 的无参数回调。声明须覆盖自身实现、Prompt、选项和嵌套依赖；调用次数、计时器等运行数据不应纳入。系统不会通过扫描任意对象属性推测完整配置，不读凭据。标准请求字段及 `prompt_path` 内容另行自动纳入。无法读取或未声明版本时，选题不复用旧校验；新校验也不能生成可确认收据。执行前后版本不同，结果不得确认；显式批次恢复逐题重验版本，不触发新的模型调用。

本约定接入多题准备、选题和批次恢复；随后扩展到整次操作，见下节。

34 项版本与父子恢复测试通过（9.429 秒），覆盖同路径 Prompt 内容变化、等内容路径搬迁、未知自定义组件拒绝、凭据不读取、版本大小限制、执行中配置变化不确认，以及改变选项后恢复不重新调用。全仓 1577 项通过（106.560 秒），日志 `.tmp_phase5_1/versions_targeted.txt`、`.tmp_phase5_1/versions_full.txt`。

## 已实现：操作级运行配置绑定

`attach_execution` 默认核对标准 A3/A2 runtime 组件图：页面理解、裁图定位/校验、分流 observer/parser/handoff/reply、外荷载、意图、安全回答及 A2 toolbox/factory。标准构造器的闭包显式声明生效选项和嵌套工具/模型版本。自定义组件及 runtime 子类须自行声明；不因类名相同就默认配置等价。原图方向适配等非默认自定义组件也不能静默跳过。

特殊适配可向 `attach_execution` 或隔离 `build_app` 传 `configuration_version`，值为有限 JSON 或返回该值的无参数回调。这是适配者对整个 pipeline 的显式版本声明，必须覆盖其全部行为相关实现、Prompt、工具及选项；不能只提供一个与配置无关的固定标签。回调在事务内使用，须有界、无副作用，不执行网络请求或写状态。测试替身使用固定 fixture 声明；不把这种替身声明作为真实模型版本证明。默认标准入口使用自动组件图，不用外部固定标签替代。

操作 producer 保存源码指纹与当前配置摘要的组合。原键重放先核对 producer，改变配置后不给旧完成结果重新授权；恢复旧配置后可按原收据正常重发。登记与抢占之间再次核对版本；执行者保存开始时的 producer，在模型发送前、状态写入及最终完成时重新验证。配置漂移会阻止新调用/写回，已返回模型的调用证据和费用仍只归属原操作。恢复与跨操作 unit 复用使用同一配置基线。

停止子题、结束整页与 reset 的命令只绑定控制实现源码及原有任务身份/版本，不依赖可能损坏的模型配置。只读控制视图在配置无法核对时仍提供合法停止/reset，不提供恢复；这些命令不会抹掉原调用费用。

97 项版本、费用、状态、操作、父子及前端入口测试通过（16.556 秒）；全仓 1586 项通过（106.368 秒），日志 `.tmp_phase5_1/runtime_version_targeted.txt`、`.tmp_phase5_1/runtime_version_full.txt`。新增断言包括配置改变后拒绝原收据、恢复原配置后复用、独立 runtime 同版本重发、登记后变更拒绝抢占、调用期间变化保留费用但拒绝结果/下一次调用，以及损坏配置时只读和幂等 reset 可用。
