# 5.4 失败、费用与父子收尾（进行中）

2026-09-09。本文件区分已实现与待验证范围，不代表第五阶段已经完成或上线。

## 已实现：调用记录与费用交接

启用执行门时，`timed_model_call` 在调用前持久建立 `execution_effects` 的 PREPARED 记录，再提交 SENT，才执行 provider function。结果及费用白名单保存成功为 CONFIRMED；网络异常、确认失败或旧租约失效保留 UNKNOWN。每次 schema 纠错是新的 call ID，继承 operation/attempt/run；不记录 Prompt、模型正文、原始 OCR 或异常消息。

Qwen 的 `request_json_with_retry` 在执行作用域内不进行网络重试；检索链创建的 Zhipu SDK client 同样将 max_retries 设为 0。未启用阶段五的 CLI/旧飞书保留现有行为。上层 schema 纠错可在已有明确响应后发起新调用；若任一调用 UNKNOWN，新模型调用在发送前拒绝，外层即使捕获异常也不能把操作提交为成功。

`execution_collectors` 保存费用 collector 的最小元数据及允许的目标账本摘要。已确认调用立即保存独立费用记录；运行结束时 `execution_cost_outbox` 先持久保存完整费用写入载荷及 fingerprint，再写实际账本。账本事务成功后单独确认 outbox，因此成本库不可用不会要求重新执行业务。

费用写入在阶段五作用域内按不可变 run/call 内容核对：同 ID 同内容复用，同 ID 不同内容拒绝覆盖。`reconcile_cost` 只重发原账本事务，核对配置绑定的账本路径摘要及载荷摘要；已提交但 ACK 丢失也不会增加费用行。冲突记为 CONFLICT。普通未启用执行门的账本调用默认仍拒绝重复 ID。

如果进程在调用记录确认后、outbox 创建前中断，`stage_unwritten_cost` 可在原操作不再持有有效租约时，从完整的确认记录生成 outcome=interrupted 的费用载荷，再调用 `reconcile_cost`。存在未确认调用、缺失用量或仍在运行的操作时拒绝推断。供应商返回内容但没有 usage 时，业务结果可保存，费用仍待核对，不能当成零。已发送但结果未知时也不把错误记录中的 0 当作确认费用。

待写费用或已停止操作的未知费用会阻止该统一执行库接受新的业务操作；原成功收据及只读状态查询仍可用。这是保守的全库准入策略，不把未落账调用排除后继续消耗全站额度。`GET /api/operation` 新增按状态汇总的 effects 和 accounting.pending_runs，不暴露 token、原输入、账本位置或原始结果。

容量与保留沿用执行库上限；调用记录另限操作上限的 20 倍，每次发送前检查磁盘和数据库空间。普通维护不清理未知调用、待记费用或账本缺失的已确认调用。尚未实现自动维护调度或生产运维承诺。

## 已实现：子题收据与文件发布

子 A2 的最后一次状态保存与 `execution_handoffs` 的 CHILD_READY 收据使用同一 SQLite 事务。收据保存冻结的公共结果、父/子任务记录外键、unit、child 状态版本及原 operation/attempt。收据保存失败时回滚该次子状态和任务历史；父流程中断时保留已确认的子结果。父 `_after_a2_response` 按 A3 → A2 → SQLite 锁序完成父状态和 PARENT_APPLIED 确认，父事务失败不回滚先前已提交的子收据。整个操作成功后收据标 COMMITTED。显式恢复入口仍待实现，保存证据不等于自动恢复。

上传副本、裁图、叠加预览和答案副本采用同目录临时文件、完整写入/同步后原子重命名。阶段五将路径、临时路径、内容摘要和发布状态记入 `execution_files`，未确认发布不能提交操作成功。新答案副本位于独立子目录，保留旧操作的答案引用；叠加预览使用唯一文件名。操作记录关联文件时暂不被普通收据清理删除，文件清理须等带引用核验的计划入口完成。

Windows 验证已修复临时文件长路径及 fsync 需要可写句柄的问题；相关现有 A2/A3 与状态/操作测试 158 项通过，父子事务与原子文件专项已覆盖父收尾前中断、父事务回滚、子收据失败回滚、精确关系和半成品不发布。

该批全仓 1521 项通过（94.632 秒）；随后新增实际答案工具连续复制不覆盖旧文件的用例，父子/文件专项 6 项通过。
