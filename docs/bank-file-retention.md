# 历史文件状态与过期证据

`tiku_shared.bank_file_retention` 为发布历史提供文件状态读取与校验。它没有清理命令，也不生成批准或过期记录；正式维护入口尚未交付。

已有独立的[文件执行核心](bank-retention-execution.md)用于原计划的过期登记、转移、清理及中断恢复。它要求可信调用者提供部署、批准、备份和引用保护，没有直接入口；这些外部核验与正式维护控制器仍未接合。

- `available`：版本目录及发布元数据可读，允许进入恢复准备；准备和完整备份仍逐文件校验，历史列表不承担全部图片的完整性证明。
- `expired`：版本文件已不存在，且原写入账本有对应的有效过期记录。保留题号、原操作、批准、回执、审计和完整发布父链。
- `unavailable`：缺少过期证据的文件丢失，或现存元数据损坏。不能准备恢复。

`PublicationStore.history` 每项增加 `files_status`；`historical` 拒绝过期或不可用目标，分别返回 `rollback-target-expired` 和 `rollback-target-unavailable`。同一不可变版本的完整文件重新恢复后可再次准备恢复，旧过期证据继续保留。现存文件仍须校验，不能用过期记录掩盖损坏。

写入器在原启动锁内创建可选的 `bank_retention_plans`、`bank_file_expirations` 表。旧档案没有这两张表时按无过期记录处理；缺少其中一张表、记录摘要不符、操作未结束、版本不匹配或审计引用不符均拒绝，不自动修补半份账本。

计划绑定当时的完整发布指针、成功发布时间形成的 30 天窗口、受保护版本、检索/管理/部署检查摘要，以及完整备份清单和隔离恢复证据摘要。校验保留当时的当前版本、窗口内版本和窗口开始时生效的版本，禁止过期清单中的发布版本属于受保护集合。文件记录须对应计划中的精确项及原操作的 `files-expired` 审计事件。

这些历史摘要只能证明记录之间一致，不能替代实际部署核验、现场引用收集、所有者授权或真正完成的备份。后续维护程序必须在原管理锁、写锁及读取互斥约束下重新核验这些条件，记录并执行具体计划。测试中的 `tests/bank_retention_fixture.py` 只为隔离测试写入合成证据，不是可调用的业务入口。

验证：`python -B -X utf8 -m unittest tests.test_bank_file_retention tests.test_bank_publication tests.test_bank_versions -q`，30 项通过（33.024 秒）；Windows 环境将本工作区 `tests` 加入 `PYTHONPATH`。包括旧格式、重开、时间窗口边界、缺失/坏记录、部分表拒绝、现存坏清单、准确文件重新恢复及原发布/读取回归。没有运行生产清理。
