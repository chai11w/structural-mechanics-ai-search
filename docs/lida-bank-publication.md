# 力答助手与飞书共用的题库发布后端

状态：已实现底层完整版本发布及读取适配，尚未接入正式飞书或力答助手写入页面，未切换 8790。开发基线为实际 8790 发布源码 `0be38081d4c81e920121fae08172843cf10aca17`。这份文档描述本次模块边界，不是第四阶段完成声明。

## 目录与职责

`tiku_shared/bank_publication.py` 提供私有 `PublicationStore`，由唯一写入服务调用；它不是模型工具。服务端必须先核验力答助手所有者或飞书维护者身份，再调用对应方法。传入 `principal/channel` 只记录已核验的身份，不构成认证。本模块不提供任意文件操作的远程接口。

三个目录必须彼此独立，备份目录不能位于 Git 仓库内：

```text
bank-store/
  active.json                 当前版本、递增发布序号、操作编号及上一版引用
  reader-gate.lock             检索共享占用与保留维护的固定锁标识
  versions/<manifest-sha256>/
    manifest.json             完整文件清单、大小与 SHA-256
    registry.json             本版永久题号对应表
    main/                     主库索引与所有题目/答案图片
    symbolic/                 字母库索引
writer-private/
  writer.lock                 操作系统跨进程单写锁
  writer.sqlite3              冻结计划、批准、执行状态、题号预留及审计
  candidates/<operation-id>/  受控业务服务生成的候选副本
  bundles/<manifest-sha256>/  校验并冻结的副本
external-backups/<operation-id>/
  receipt.json                具体计划、批准及基准发布版本
  bank/                      写入前完整版本；首次安装尚无旧版本
```

题库业务服务必须提供实际校验器：核对题号表、Excel、题图、全部答案及变更范围。发布模块的文件校验不能代替题目语义和权限校验。它拒绝软链接、junction、硬链接文件、路径别名、遗漏和哈希不符的内容。

## 写入流程

1. 共用 `reserve(owner, draft_id)` 预留永久题号；相同草稿重试返回同一题号。安装时仍需迁入原有题号及草稿预留关系，不能重新给已有题编号。
2. 受控业务服务在私有候选目录生成完整版本。`prepare` 调用业务校验器并冻结整个版本，与具体操作、基准发布序号及版本、变更摘要绑定。相同操作重复提交不得更换内容。
3. 所有者入口调用 `review` 展示原题、变更后内容和具体计划，取得只供可信确认入口使用的 challenge；状态查询不返回 challenge。
4. 所有者页面或可信飞书确认调用 `approve`，绑定身份、渠道、计划摘要和 challenge。飞书确认一次即可，不需要再去力答助手确认。模型不接收批准凭据，也没有批准或执行工具。
5. 私有调度器调用 `execute`。在跨进程单写锁内核对批准与当前版本，核验仓库外备份，复制完整候选版本，再原子替换 `active.json`。改草稿前用 `cancel` 撤销原计划及批准；已发布的操作不能当作草稿撤销。
6. SQLite 执行日志与实际发布指针共同判断结果。发布前进程中断可继续原操作；发布后进程中断恢复为真实成功，不能再次写入。结果未核实不能报告入库失败或成功。审计可分页读取。

发布序号单调递增；即使恢复相同文件内容，也不能复活旧批准。生产回滚还需由业务服务生成具体的恢复计划，保留后来分配的题号及退役身份，经所有者批准后再执行。不能直接用旧目录覆盖当前版本。

## 检索读取

`TIKU_BANK_STORE` 未配置时，保留原有读库方式。受控上线后，8790、飞书和 CLI 的读取端通过该变量定位发布目录；`tiku_shared/bank_versions.py` 为一次读取固定版本，线程池通过现有 ContextVar 传播保持一致。正在使用的旧候选继续读取其原版本及完整答案列表。

离线初始化增加 `PublicationStore.import_reservations(migration_digest=..., reservations=...)`，供安装器把已审核的旧题号及草稿预留关系导入全新写入器。它不生成替代号码、不批准或发布，没有业务 HTTP/模型入口。完整清单在单写锁和一个 SQLite 事务内导入；首次导入要求没有旧操作、预留或发布版本，同一摘要重试必须逐条核对已有绑定，冲突时拒绝覆盖。原题记录（含退役身份）及已取消草稿都保留题号。平台侧迁移清单固定旧题号表、原快照、任务文件和当前完整题库摘要；不根据旧 Excel 行号猜测身份，不把另一份验收题号表覆盖到原表。

受管模式下，`search.py store` 及直接索引写入拒绝修改发布版本；搜题时的历史路径修复只用于解析，不写回索引。CLI/飞书的检索缓存通过 `TIKU_SEARCH_STATE_DIR` 放在独立运行目录，不能放进发布题库。各服务应使用各自的缓存目录，不能把旧默认答案输出目录当作共享业务状态。

旧批量写入、索引生成和字段回填入口已补受管拒绝，具体清单见 [旧写入口治理](legacy-bank-writers.md)。受管 CLI 取答案只显示文件引用，飞书单题/多题直接读取当前发送者所选候选的全部答案；都不再清空共享答案输出目录。相关限制仍须与 Windows 服务身份、生产目录 ACL 和旧工作区治理共同部署。

飞书已增加原始回调验签、加密事件解码和独立维护者身份校验；受管模式的旧新增/删除写入方法拒绝直接写索引与图片。详见 [飞书统一写入的事件入口](feishu-managed-callbacks.md)。飞书相关 19 项测试通过，包含真实 Bridge 线程中的身份传递及未验证/非维护者拒绝；没有向真实飞书发送消息。

## 历史清理前的读取保护

`tiku_shared/bank_readers.py` 为受管题库增加独立的操作系统共享锁。读取端只读打开发布根目录的 `reader-gate.lock`，不调用写入服务，不创建或改写题库文件。Windows 使用 `LockFileEx`，其他平台使用 `flock`；清理维护尝试独占同一锁，有读者时立即返回 `BankReadersBusy`，不排队阻塞后续读者。新版本发布仍沿用原单写锁与指针切换，不取得这个独占锁，正在读取的旧版本可以继续使用。

保护覆盖版本/清单读取之前、旧候选题目定位与答案复制、Agent 会话载入到 SQLite 保存，以及网页 JSON/流式业务执行到展示图片持久化。飞书的受管检索到独立回复图片保存也在同一范围内；旧 Bridge 路径则持有到回复图片交给传输接口之后。接口已经复制到自己目录的图片继续按原会话规则提供。底层检查点原题图片读取也取得共享锁。

同一线程中的嵌套调用复用锁；线程池中的工作自行持有句柄，不复用从调用线程传播过来的“已加锁”标记，因此后台工作比调用者晚结束时仍受保护。正常退出主动释放，进程异常退出由操作系统释放。缺失、坏内容或链接形式的锁文件拒绝，不由检索端自动修复。读取被已持有的短时维护独占锁挡住时等待释放，最长 30 秒；维护必须把备份、哈希、递归删除和服务等待放在独占区间之外。

显式 `BankVersion(..., version=None)` 仍用于可信 worker 的私有副本验证。此时内部嵌套读库沿用指定副本，不因进程环境中的 `TIKU_BANK_STORE` 指向不可用目录而接触生产题库。真实发布版本则按自己的发布目录取得读取保护；普通受管读取缺少锁文件仍然失败。该私有 Python 对象不作为模型参数提供。

写入器构造时，在现有写锁内初始化固定锁文件。已有受管安装需要先完成程序升级和这项初始化，再启动新版读者；旧版读者即使看见这个文件也不会遵守该协议，因此清理前还须核实所有实际读取进程的程序版本。锁文件位于版本目录之外，保留其文件身份，不随历史目录删除或替换。完整恢复应还原它的原字节，新安装或旧格式恢复缺少时只能由受控安装/写入器补建。

`maintenance_gate` 是内部维护原语，不是删除授权，也不是模型工具。安全清理还须停住管理写者、持有原写锁，并在独占区间内重新核验持久候选与任务引用、30 天边界和具体清理计划。当前只接合读取保护，未实现历史文件到期状态或清理入口；不能仅因取得独占锁就删除旧目录。
