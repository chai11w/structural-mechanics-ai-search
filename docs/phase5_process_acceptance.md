# 阶段五：独立进程故障验收

本批为 5.5 集成验收的一部分。`tests.test_execution_processes` 使用 Windows spawn 创建独立 Python runtime；故障点直接 `os._exit(91)`，不运行异常处理或 finally。另一个 SQLite 库模拟供应商收到的请求，记录原 operation ID；重启后的执行库和费用库与前进程共用磁盘文件。无外部模型网络调用。

租约测试使用固定测试时钟，重建 runtime 时推进 6 秒越过测试租约 5 秒；不修改生产时钟或生产租约。父子案例使用固定页面、实际裁图及 FakeTools，计费模型替身只放在子题识别处，每次 120 tokens。

| 场景 | 需要保持的事实 | 已验证结果 |
| --- | --- | --- |
| 登记后、抢占前退出 | 请求尚未执行，可继续原操作 | 重启执行一次，原键再发只读收据，attempt 和供应商请求各 1 |
| 供应商已收到请求、返回前退出 | 已发送但结果未知 | 原键不重发，调用保持 UNKNOWN，用量计划不能按零结算 |
| 响应返回、确认记录前退出 | 外部已有调用，缺少可信本地结果 | 重启不重发，UNKNOWN 保留 |
| 响应确认、业务完成前退出 | 已确认费用不应丢失 | 原 collector 的 closed 仍为 0；失权后依据记录补账一次，120 tokens；业务不伪造成功 |
| 成功事务提交后退出 | 已成功但响应未交付 | 原结果重发，供应商请求/attempt/费用调用各 1 |
| PREPARED 后、发送标记前退出 | 请求未发送 | 审核后标 NOT_SENT，保留 call_id，不生成用量响应；原 run 零调用，业务保持 UNKNOWN |
| 两个独立 runtime 同键竞争 | 只一个执行者能发请求 | 一个 BUSY，另一个在测试放行后成功，供应商收到 1 次 |
| A3 已进入 A2_ACTIVE、子 A2 调用前退出 | 没有子收据，不得假装可恢复 | 父状态保留 A2_ACTIVE，恢复拒绝，新增供应商请求为 0 |
| 子 A2 保存后、父收尾前退出 | 子结果必须可核对且不能串题 | CHILD_READY 的 parent/child/unit 外键匹配；显式恢复后 COMMITTED，不重识别或重收费 |
| 父状态保存后、操作完成前退出 | 不重复执行已完成子流程 | PARENT_APPLIED 可恢复为 COMMITTED，原键重发仍仅 1 次子识别和 120 tokens |

NOT_SENT 收尾另验证：原未知操作不会自动重新执行；显式 reset 后允许新操作；退出代次且到达保留期限后，已经结清的未发送记录可以进入受控清理，不永久占用容量。混合一条确认、一条准备记录只计确认部分；审核后准备记录变成 SENT 时计划失效，不做“未发送”收尾。

当前进程专项 10 项通过（18.579 秒），费用/清理联合批次 50 项通过（19.328 秒），全仓 1601 项通过（128.364 秒）。日志分别为 `.tmp_phase5_1/process_a3_final.txt`、`.tmp_phase5_1/process_accounting_final.txt`、`.tmp_phase5_1/process_full.txt`。

这些证据支持 A01/A06 的跨进程文本竞争、A07～A09 的持久故障窗口、A11 的父子关系、A14/A15 的费用事实，以及 A16 的未发送记录保留边界。它们不替代全部 HTTP 图片并发、离线迁移/回退和 A01～A18 的最终逐项验收。
