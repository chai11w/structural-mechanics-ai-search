# 受管题库的旧写入口治理

正式新增、修改、删除沿用同一私有写入器和所有者一次确认。以下脚本只保留给尚未迁移的旧环境；设置 `TIKU_BANK_STORE` 后，它们不能直接修改 Excel、备份旁路副本或执行批量识别入库。环境变量检查不是操作系统权限，正式切换还必须配置独立服务账号和 NTFS 权限。

## 已收窄的入口

| 入口 | 受管模式行为 |
| --- | --- |
| `search.py store`、`store_chapter_excel`、路径自动修复 | 旧存储/索引写入拒绝；路径解析不写回 Excel |
| 飞书原 `FeishuStoreService` / `FeishuDeleteService` | 不直接执行旧存储/删除，管理流程改用私有写入器 |
| `build_index.py` | 批量处理和保存 Excel 在识别/临时输出之前拒绝 |
| `scripts/apply_main_bank_update.py` | CLI 拒绝；直接调用写入函数也拒绝 |
| `scripts/build_symbolic_bank.py` | CLI 在创建目录及生成工作簿之前拒绝 |
| `scripts/store_unindexed_questions.py` | CLI 在扫描、识别及输出之前拒绝；追加、应用与备份函数拒绝实际写入 |
| `scripts/backfill_letter_bank_dimensions.py` | CLI 拒绝；直接回填及备份函数拒绝实际写入 |
| `scripts/normalize_excel_load_units.py` | CLI 拒绝；直接规范化及备份函数拒绝实际写入 |
| `scripts/write_symbolic_structure_types.py` | CLI 在读取模型凭据及识别之前拒绝；写工作簿与备份函数拒绝 |

上述七个维护命令在受管模式整体退役，包括其中的 CLI 干跑入口，避免旧默认报告目录和识别缓存继续进入生产调用。具有明确 `dry_run=True` 参数的内存/只读函数仍可被隔离验证复用，原有荷载转换、路由、识别函数保持可导入。漏索引追加的干跑也不再创建目标题库目录。

不设置 `TIKU_BANK_STORE` 时保留既有旧环境行为。这意味着旧工作区、桌面脚本或手动清空环境变量仍可能绕开代码检查：上线时必须保护生产发布目录和冻结旧库，撤销旧服务/个人进程的写权限，并核对实际计划任务启动源。不能把本文件说成所有历史脚本已获得不可绕过的写入限制。

## 取答案的输出边界

受管 `search.py answer` 和 `scripts/search_by_loads.py answer` 根据运行目录的候选缓存解析全部答案，只显示/返回实际只读文件引用；不再清空配置的共享 `answer_output` 目录。

受管飞书单题/多题取答案使用当前发送者会话中选定的候选路径，直接返回其原发布版本的全部答案，不使用全局最近搜索排名，不导出到共享目录，也不截取最后三张图片。重复查询和后续发布不能让旧候选换到另一版本。8790 的 Agent 答案工具继续使用独立运行目录。

未迁移旧模式的 CLI 和飞书行为保持原样。生成识别报告、评测图片或其他业务运行文件的脚本不因此获得生产目录写权限；它们也不能作为正式管理模型的任意脚本入口。

## 验证

`test_legacy_bank_writers.py` 验证七个实际 CLI 入口、写入/备份函数、干跑目录边界、旧环境真实 Excel 修改以及受管识别所需纯转换函数。`test_managed_answer_delivery.py` 验证六张答案、旧发布候选、两个飞书发送者/单题多题、错误路径拒绝及共享输出目录不变。测试只在临时目录进行，不发送真实飞书消息。

本轮与发布、读取、飞书事件/存储和 Agent 工具一起回归，共 85 项通过。平台侧继续验证实际私有 HTTP 和完整候选构建；生产账号、计划任务、目录 ACL 与真实渠道验收仍未切换。
