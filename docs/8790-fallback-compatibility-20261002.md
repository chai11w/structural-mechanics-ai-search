# 8790 既有兜底与后台任务确认兼容修复

## 结论与对照范围

8790 的业务兜底仍在，但后台执行层原先要求所有模型调用都为 CONFIRMED。复筛超时后，业务已经返回粗筛结果，`OperationStore.finish` 仍将整个任务改为 UNKNOWN。自动裁剪转手动、手动裁图保留草稿等分支存在同样冲突。

线上故障记录中，上传操作 `d3ecdf31d9ce4ab6a0298a7371ea2689` 成功；随后选题操作 `fb27341531094b818b276b7e18222f7c` 的 9 次 Qwen 复筛有 7 次确认、2 次网络超时，最后变为 UNKNOWN。这说明外部调用确实可能失败，同时主线没有正确交付已有兜底结果。

对照的是本地历史参考 `ac32395` 与当前固定发布 `9563f5f` 的源码。历史参考中的 A3 自动裁剪、校验、整页理解与手动草稿兜底仍可找到。`ac32395` 只是此前演示前端的匹配证据，不能据此认定当前演示后端版本。演示浏览器读取本轮被权限检查拒绝，未绕过读取。用户后来也报告演示调用失败，因此不能据演示曾成功断言模型服务始终正常。

Git 记录显示，严格模型确认门在 `de86d54`（2026-09-09）加入，早于七阶段上线/回退；尚无证据把此冲突归因于那次回退。

## 分支核对与修复

| 场景 | 已有业务处理 | 本次执行层交付 |
| --- | --- | --- |
| 形状复筛部分或全部超时 | 返回初筛候选及未完成提示 | 保存原初筛排序，页面可继续选择 |
| 杆长复核失败 | 使用原有默认复核分值继续 | 保留候选，同时补齐线程中的执行与费用上下文 |
| 可选结构类型识别失败 | 跳过结构类型筛选 | 继续检索 |
| 旧多题探测失败 | 继续单题识别 | 保留原路由兜底 |
| A3 自动定位/裁图校验/外荷载校验失败 | 自动准备失败项转手动裁剪 | 保存选题状态，可进入手动裁剪 |
| 手动裁图校验/外荷载校验失败 | 保留裁剪草稿 | 保留草稿及提示，供用户继续操作 |
| 整页理解失败 | 保留原图并提示重试 | 保存错误回复，显式新操作可重试 |
| A2/A3 意图模型失败 | 请求澄清 | 交付澄清提示 |
| 安全回复或预检回复模型失败 | 使用固定回复 | 保留已确定的路由和固定提示 |
| 可选本地裁图写入失败且未发布 | 转手动裁剪 | 清理自身临时文件，记 ABORTED，交付兜底 |

修复不是把任意异常吞掉。实际题目识别等缺少可用结果的必要步骤，不伪造识别或检索结果。没有业务兜底的调用、仍在途的 SENT 调用、文件已发布而收据丢失、业务落盘前进程中断，继续保留未确认状态。

## 一致性与验证

模型边界为真实已落盘的失败异常附带 call ID；已有兜底分支按限定类型接纳。接纳记录只属于当前 writer/attempt，在业务回复成功保存时一并写入内部任务收据。模型及费用 UNKNOWN 原样保留；刷新或重连只读取已保存回复，不重发模型请求。原 UNKNOWN 任务不自动重放。

CLI/旧飞书未启用执行 observer 时接纳函数为空操作，保留原检索与排序逻辑。未改章节、荷载类型、Prompt 或数据源，也不涉及题库资产写入或 NATAPP。

新增故障注入测试经过实际后台任务/状态保存边界，覆盖并发和顺序复筛超时、全部候选超时、自动转手动、草稿保留、明确重试、固定回复，以及在途调用/确认丢失/落盘前中断的边界。所有外部模型由隔离替身代替，不产生模型费用。真实公网浏览器的登录、过期、重连、新对话和撤销验收与模型故障注入分开记录；前者不冒充模型端到端成功证据。

发布结果和回归数量在部署完成后补记。
