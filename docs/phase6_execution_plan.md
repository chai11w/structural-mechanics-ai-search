## 1. 核心契约

### 1.1 接收、执行、观察三个边界

- **接收**：沿用逻辑 operation key，绑定稳定 identity、session/epoch、expected state_version、操作类型、目标、输入摘要和 producer。
  输入载荷落入隔离私有存储；图片使用服务端生成的不可变受控引用，不持久化任意客户端路径。
  输入可读性/摘要/大小、容量与授权检查通过，operation 与派发记录原子提交之后，才返回接收凭据。
  ACK 丢失时先按原键查登记状态；不存在才允许同键重试提交。单凭超时不生成新键。
- **执行**：后台持有完整生命周期、租约与阶段 reporter。领取只经既有 operation 权威；重验 epoch、目标版本、producer、授权、额度、待对账与排队期限。
  worker 不持有 Request、Cookie 明文、上传对象或某个客户端 event loop；内部 A3→A2 继承原 writer 和费用归属。
- **观察**：身份和会话范围内按操作凭据查询状态、最新进度、结果；重连、轮询、订阅不得领取任务、刷新租约、调用模型或创建业务操作。
  订阅者慢或断开时舍弃中间进度，终态与结果从持久权威读取。

派发记录仅描述“等待领取/已领取/已结清/已撤销”，业务结果和不确定性仍以 execution_operations/effects/receipts 为准。
一个 operation 只关联一个后台调度单元；不另建可与原操作状态冲突的业务权威。
持久输入包含后台必需的原文本/参数，属于私有执行数据，不得混入 Trace、Checkpoint、公开 health 或浏览器日志。
上传/JSON 限制、记录数/字节/磁盘容量必须在接收前生效；最晚在 6.2 冻结具体存储限额、文件生命周期及孤儿清理规则并测试，再允许持久 ACK。

### 1.2 结果和进度

- 操作 SUCCEEDED 表示本次业务调用已完成，可能结果是等待补充/选题/裁剪/候选；不代表整个 workflow 已答完。
- 接收响应只承诺已接收；HTTP 202 或流建立成功不能冒充搜题成功。
- 持久业务收据、可展示结果、媒体/Response 关联分别核验。断线后仍完成结果准备，重新观察得到同一逻辑结果和反馈归属。
  结果准备失败时保留原业务收据，允许有界地修复交付，不重新搜索或调用模型。
- 结果中的历史快照与“现在允许做什么”分开：旧结果可展示，动作必须用当前权威状态重新授权，不能把旧 epoch/revision 复活。
- 建议首版持久保存最新进度快照和单调版本，观察缓冲只保留有限最新状态。
  不要求重播每条进度文案；游标断档返回权威快照，不因缺失中间消息重执行业务。最终结果不依赖内存进度缓存。
- 后台业务 Trace 与提交/观察 HTTP Trace 分开关联，各自只有一个终态；观察连接断开不能抢占后台的失败/成功终态。
  Response/反馈 ID 绑定后台最终结果，重复观察不得生成重复可评分回复。

### 1.3 排队和控制

- 保留现有并发、排队及等待预算，不因引入 worker 扩大模型并发；A3 内部逐题并行也不得绕过原限额。
  派发队列与 runtime gate 的额度必须统一计算，避免双重排队、重复计算 55 秒或无界堆积已接收任务。
- 排队期限由服务端首次接收时记录；刷新、重连、原键重发、服务重启不重置期限。超时且确认未开始时明确结束派发，零模型调用/费用；不会暗中再次排队。
- 同 session/epoch 未完成操作继续互斥。用户新操作不能靠后台排队绕过旧动作的 expected version 和目标绑定。
- 断线不是取消。显式停止/结束本页/reset 仍走有界、版本绑定、幂等控制通道，不能排在长模型调用之后等它完成。
- 已发出的模型调用不承诺中途停止。控制赢得状态竞争后阻止新调用与晚到结果发布到当前态；原调用证据和费用保留。
- 无 Web Lock 的浏览器继续按原规则拒绝任务变更入口；不借阶段 6 放松多标签页保护。

## 2. 事件行为矩阵（后续实现的目标规则）

| 事件 | 队列/运行处理 | 用户看到什么 / 禁止什么 |
| --- | --- | --- |
| 上传尚未持久接收就断线 | 未提交的 staging 不可领取，清理孤儿；若实际上已提交，按原键能查到 | 先查询接收状态；不能仅凭没收到 ACK 判定未执行 |
| 已接收、尚排队时刷新或关闭网页 | 队列继续，沿用原截止时间 | 重连显示原任务排队；不得因关闭观察流撤销它 |
| 运行中断网/关闭页面 | worker 继续，独立持久化进度和结果 | 重连查看原操作，不重新上传/调用 |
| 业务完成、结果准备尚未完成 | 保留业务收据，独立完成/核对交付 | 显示处理中或结果准备失败，不能重新搜索作为补救 |
| 结果可读后反复刷新/多标签页观察 | 只读同一收据与结果 | 不新增调用、计费、重复反馈对象；旧结果不能授权新动作 |
| 到达排队截止时间 | 确认未开始则结束派发；若领取竞争已发生，按事务胜者处理 | 明确排队超时或真实运行状态；原键查询不会偷偷复活排队 |
| 新指令、换题与旧标签页并发 | 按 session/epoch/expected version/target CAS 裁决 | 不把旧输入执行到新题，不因新订阅刷新动作授权 |
| 会话自然过期 | 服务端裁决；未开始任务不再启动，运行者不再获得新执行授权；已发出调用仍记证据/费用 | 保留原有本地历史展示与失效提示，不自动重建会话；观察不续期，原有合法状态保存续期规则不擅改 |
| 仅关闭页面或网络 Cookie 暂时不可用 | 不等同注销或撤销；后台按已持久化的有效授权边界运行 | 新观察请求仍需正常认证 |
| 显式注销 | 关闭该登录会话的新提交/观察；未开始任务不再领取，运行中的新调用停止准入 | 不暴露结果给失效登录态；已发送调用仍结账。注销不是删除费用/业务历史 |
| 邀请码禁用/删除、额度耗尽、出现待对账 | 接收/领取/模型发送边界重验；不得启动被拒绝的新调用 | 给出对应受控状态，不能靠旧 Cookie 或已排队绕过控制库 |
| 停止子题/结束本页/reset | 控制幂等；撤销关联排队或使旧 writer 失权；reset 更换 epoch | 旧结果可留作记录但不写回新会话；不清除原费用 |
| 服务正常关闭/发布 | 停止接收/领取，给在途有限 drain 时间；保护输入和证据，记录未结清状态 | 禁止把被迫中断的任务报告为完成；不按端口杀无关进程 |
| 服务死亡：完整指令未领取 | 重启只在版本、授权、期限、容量和输入全部有效时自动领取一次 | 不要求客户端重传正文；不续排队期限 |
| 服务死亡：已领取但结果不明 | 按原租约/token 隔离旧执行者，分类 UNKNOWN；只恢复已证明安全的本地步骤 | 不自动重发 SENT/UNKNOWN 模型调用；需要核对时明确显示 |
| 子题已确认、父级未收尾/部分 unit 完成 | 复用准确父子/逐题收据，核对范围与版本后恢复本地提交 | 已完成子题不重复调用；未知 unit 不冒充成功 |
| 新版本/配置与 queued 或结果 producer 不同 | 未经过兼容确认不得领取旧指令或重新授权旧结果 | 明确版本不匹配并保留证据；部署时先制定 drain/兼容方案 |
| 输入、媒体或结果过期/损坏/容量耗尽 | 接收失败不发成功凭据；已接收任务给真实失败/结果不可用，保留权威状态 | 不从当前题库偷偷重算来补旧结果；不把证据存储当无限业务队列 |

自然过期、注销、撤销的具体控制校验由 6.2/6.5 实现，场景证据见 6.5 交付文档；完整发布门仍由 6.6 汇总核验。
worker 对运行中图片/原文与未知效果证据的保护必须与现有 retention 协调；不能因为页面不再观察就立即删输入，也不能通过无限续期规避容量门。
