# 旧副本转移、清理与中断恢复核心

`tiku_shared.bank_retention_execution._execute_locked` 实现已批准文件清单的过期登记、原目录转移和清理，以及同一操作的中断恢复。它是内部函数，没有命令行、HTTP、模型工具或批准入口。正式维护控制器尚未接入；调用者必须先落实真实部署权限、所有者批准、完整备份及隔离恢复证据，并持有全部管理服务锁和原写锁。不能从文件核心的单独测试推断生产清理已可启用。

## 调用者必须提供的保证

- 精确的原计划摘要和可信所有者批准回执。回执记录原摘要、主体和批准时间，重试不能换成另一份回执或扩大文件范围。
- 完整的管理/检索引用来源、实际部署身份与权限核验，以及原清单与题库版本、文件和备份的对应关系。文件核心只验证计划/账本内部一致性，不能证明这些外部证据真实。
- 在整个调用期间持有管理服务锁及写锁；文件核心的内部名称带 `_locked`，不会另行抢占或替代这些锁。
- `check_freshness` 在三个检查点必须明确返回 `True`：`before-record` 核对外部依据；`after-record` 核对本操作新增的精确账本/审计行，再采用新的写入账本指纹；`before-move` 在读取独占锁内重验原活跃保护。异常、`False` 或无返回值均拒绝。最后一个检查只能校验已捕获的轻量保护，不能停止服务、全量哈希或等待。

正式接合仍需由维护控制器实现以上检查，并处理原清单失效、所有者批准及调度。当前只读清单命令的 `cleanup_enabled=false` 继续有效，不能用测试中的固定返回值代替这些保证。

## 文件与账本顺序

1. 在写入器私有 `retention/<计划号>/request.json` 中持久保存原计划、批准和每份副本的完整文件/目录清单。文件清单通过原版本的不可变 manifest 校验；额外路径、摘要变化或旧请求不一致拒绝。
2. 核对原目录与本计划独占的转移目录。尚未记录过期前的资料丢失继续按不可用处理，不能补造过期记录来解释丢失。在原 SQLite FULL 事务中一起登记计划、文件过期记录及原操作的审计事件；重复执行验证原记录，不重复记账。
3. 在短暂的 `maintenance_gate` 内重验发布及引用保护，逐个把原目录转移到其所在组件的 `.retention-trash/<计划号>/<类型>/<编号>`。转移路径保持同一组件、同一卷。读取正在占用时拒绝，不等待清理机会；此时已有记录对应的原文件仍显示可用。
4. 全部转移完成后释放读取独占锁，持久记录 `purging`，再校验并逐个删除该计划转移目录中的已知文件。代码不调用递归删除；未知内容、链接、位置歧义、路径越界或文件摘要改变时拒绝，未知文件保留。
5. 文件处理结束记录 `done`。原题号、操作父链、批准、回执、过期证据和维护请求继续保存。转移目录的空父目录也保留；这些元数据的容量不能算作已经释放。

已登记过期但原文件仍存在时，历史状态仍为可用；转移后才显示过期。只有持久进度已进入 `purging`，才允许清理目录中的部分已知文件已经消失。`staging` 阶段原位置和转移位置都缺失、两个位置同时存在，或已完成目录重新出现，都拒绝猜测。

同一计划重试根据原请求、账本和实际两个位置继续；新发布使旧计划失效，不能以旧批准处理新的题库。缺失或损坏的进度不能被当作成功。清理始终在 C 端独占读取锁之外进行；完整哈希和外部备份也不得放进此锁。

Windows 进程退出后的句柄释放和文件/SQLite 持久化已纳入测试，不能以此宣称设备断电或存储控制器故障的恢复保证。正式部署仍需完成对应验收。

## 新旧恢复策略兼容验证（2026-09-20）

原测试使用当前 `prepare` 创建 `retained-versions` 发布，却无条件把
`backups/<operation_id>/bank` 加入清理清单。新策略不生成这份额外整库副本，因而复现
5 个测试方法中的 7 个失败断言、2 个错误。这是测试夹具与冻结策略不一致，不能靠
跳过缺失目录、减少安全断言或恢复每次整库复制来让测试通过。

修复仅调整隔离测试夹具及文档，生产发布与清理代码不变。旧策略使用发布测试已有的
升级前冻结计划夹具，在所有者批准前固定旧摘要，再走真实 approve/execute；新策略
继续使用当前 prepare。清单按冻结策略确定，不根据文件是否存在临时删减：

| 发布历史 | 可清理旧副本种类 | 必须保留 |
| --- | --- | --- |
| 全部新策略 | published、candidate、bundle，3 项 | 旧/边界/当前操作的全部回执，受保护发布版本 |
| 全部旧策略 | 上述 3 项及 boundary 操作保存的旧 receipt-bank，4 项 | 全部回执、受保护发布版本、未列入计划的当前操作整库备份 |
| 旧策略升级到新策略 | 4 项，保留旧备份清理覆盖 | 全部回执、受保护发布版本；新操作不产生额外整库备份 |

每组都覆盖重复执行、读者占用、保护核对失败、未知文件和清单篡改、登记前文件丢失，
以及五个位置的真实子进程退出：请求持久化、账本提交、目录转移、清理进度落盘和首个
文件删除后。新增“清单要求的副本在开始前缺失”测试，验证不记过期、不移动其他文件；
恢复原副本后沿用同一计划完成。旧操作的计划、摘要、批准、结果与状态，以及全部批准
回执逐字节保持不变；受保护版本完整可读，过期行与审计数量精确且不重复。
